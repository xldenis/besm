# harness: end-to-end tests for PP-BESM

`besm_test.py` pushes a PP-BESM programme through the whole toolchain and checks what the compiled programme computes:

1. **encode**: `pp-besm print` turns the `.pp` source into the tape image loaded on MD-2.
2. **compile**: `besm-vm trace` runs the compiler (`boot.txt`, `mp1.txt` on MD-0, `mp2.txt` on MD-4, `mp3.txt` on MD-3). When PP-3 finishes, the programme is on MD-1, and PP-3's `final-header` cells hold the final layout (C0\*, K0\*, γ0\*, O0\*, M0\*, R0\*, Rf\*).
3. **run**: MD-1 is loaded as the instruction store and executed from K0\*+1.
4. **check**: the final store and any `PN` output are compared against the spec.

Needs Python ≥ 3.11, a built `pp-besm` (`stack build` in `pp-besm/`, or point `PP_BESM` at the binary) and cargo. besm-vm is rebuilt automatically unless you pass `--no-build`, or you can point `BESM_VM` at a binary.

## Usage

```
harness/besm_test.py run examples/sum_loop.pp --disasm   # compile, run, report layout/values
harness/besm_test.py test                                # run every spec in harness/tests
harness/besm_test.py test harness/tests/sum_loop.toml -v
```

Useful options: `--keep DIR` keeps the tape, MD-1 and programme images. `--images DIR` uses compiler images from somewhere other than `besm-vm/`, e.g. ones freshly generated by `tools compile -o DIR --source-map-dir DIR`. `--max-steps N` sets the instruction budget per VM run (default 2M; compiling `sum_loop` takes far less). `--start ADDR` overrides the entry point.

## Specs

One TOML file per test:

```toml
source = "../../examples/sum_loop.pp"   # relative to this file, or give `program = """..."""` inline
# start = 7                             # optional entry point override
# xfail = "reason"                      # known failure: reported, doesn't fail the suite (XPASS does)
# skip = "reason"

[expect]
compile = "stopped"      # default; also "error", "infinite-loop", "step-limit", "timeout"
run = "stopped"          # default
printed = ["08a0000000"] # optional: exact list of PN outputs (39-bit hex)
tolerance = 1e-9         # relative tolerance for numeric comparisons

[expect.values]          # variable quantities from section 3, by name
b = 45

[expect.memory]          # raw cells: a number compares the decoded float, a string the hex word
"5" = 10.0
```

Named values work for the entries of section 3 ("List of Constants and Variable Quantities"). PP-3 lays block C out in that order right after the parameter counters, so entry *i* is at C0\* + 1 + *i*. Use `[expect.memory]` for anything else, such as variable-address blocks.

The suite exits non-zero on any FAIL, XPASS or harness ERROR.
